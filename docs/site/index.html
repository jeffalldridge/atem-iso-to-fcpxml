From the SSD to the edit

Three steps.
One new file.

  1. Choose the recording.

    Mount your SSD. Right-click the native ATEM .drp file or its folder, then choose Quick Actions → ATEM ISO to FCPXML.

  2. Pick picture and sound.

    Select the camera inputs you used and a WAV for the soundtrack. Add mic inputs as separate audio angles, or leave them out.

  3. Open in Final Cut.

    Import the new .fcpxml. You get a multicam clip, a Live Edit project, and the selected source clips. Trim, change a switch, add titles, and export.

Get the Quick Action ↓

Install the Finder Quick Action

  1. Download and unzip ATEM-ISO-to-FCPXML-Quick-Action.zip from the release page.
  2. Double-click ATEM ISO to FCPXML.workflow and choose Install.
  3. Right-click a recording in Finder to run it.

Requires Python 3.9 or newer. Install Apple’s Command Line Tools with xcode-select --install, or use Python for macOS.

Command line

Clone the repository, then run the single Python file:

git clone https://github.com/jeffalldridge/atem-iso-to-fcpxml.git
python3 atem-iso-to-fcpxml/atem_iso_to_fcpxml.py "/Volumes/ATEM SSD/Live Show"

Before you download

Know what’s tested.

ATEM Mini Pro ISO · 1080p60 · Final Cut Pro 12.4

Verified with two real recordings and an XML round trip in Final Cut. Other models, rates and firmware still need real-world validation. FCPXML 1.10 targets Final Cut Pro 10.6 and later; older versions have not been tested here.

A few useful answers.

Does it use the WAV files?

Yes, when the matching WAV is present. Camera angles pair ISO picture with that input’s uncompressed audio. Missing camera WAVs fall back to MP4 audio with a warning. You choose one soundtrack for the live edit; the mic inputs can be separate audio angles.

Will it work with my recording?

Real imports were verified with ATEM Mini Pro ISO recordings at 1080p60 in Final Cut Pro 12.4. The converter writes FCPXML 1.10 for Final Cut Pro 10.6 and later. Other models, firmware and frame rates have not been verified with real recordings. Keep the recording’s internal files and folders intact; custom input labels and a renamed recording folder are supported.

Does it change or upload my footage?

No. Conversion runs locally and creates one .fcpxml file beside the .drp. The original recording stays intact. Final Cut’s import preferences control whether media is copied or linked. Keep the SSD connected until any copying finishes. The XML contains media paths, so treat it as private.

Will it import into my selected event?

The XML creates a named event containing the multicam, project and selected source clips. It does not target the currently selected event. Move the imported items to your preferred event afterward if needed.

What should I check before exporting?

Check sync, the start and end of the project, and any marked sections. Different source start times and short files generate warnings but are not automatically corrected. Without program video, unsupported sections become gaps that also interrupt audio. Media Player changes during recording are not fully reconstructed.

Do I need DaVinci Resolve or ffmpeg?

No. The converter reads the native ATEM switcher log directly using one Python 3.9+ standard-library file. It does not require Resolve, ffmpeg, Homebrew, a server or an internet connection during conversion. A .drp exported by Resolve is a different format and is not supported.
