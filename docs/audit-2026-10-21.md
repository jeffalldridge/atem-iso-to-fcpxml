# Product audit — October 21, 2026

This audit covers the Python reference, Swift engine and CLI, SwiftUI state and layout, Finder workflow, installer, build/release automation, public documentation, and website publishing contracts. Changes are local for owner review; no push, release, signing-secret change, or deployment was performed.

## Assessment

The focused conversion workflow is sound enough to keep improving without replacing its architecture. Preserve the verified compound/multicam output, explicit overwrite consent, local-only processing, and small dependency footprint. The larger weaknesses are at the boundaries: malformed metadata, UI defaults versus engine defaults, release failure reporting, and documentation left over from superseded implementations.

The previous UI pass improved the native controls. Another visual redesign is less valuable now than testing the real workflows and closing the failure cases below. This is a bounded source and regression audit, not a claim that every malformed input, device, or macOS version has been tested.

## A suspected defect that did not reproduce

The forced-output path looked suspicious when the destination did not exist. The new regression proves that Foundation's current implementation creates it on this Mac, refuses unapproved replacement and symlinks, and replaces a hard-linked output without damaging the linked media. No output-writer change was justified. Keep the regression; verify exFAT on actual recording media separately.

## Remaining priorities for owner review

1. **Numeric robustness remains a hardening project.** `Rational` uses fixed-width Int arithmetic; rejecting several bad headers does not make all arithmetic overflow-safe. Add subprocess fuzzing of MP4/WAV/DRP boundaries, explicit supported ranges shared with Python, and checked/cross-reduced arithmetic before claiming arbitrary corrupt-file resilience. Do not substitute floating-point timing.
2. **Close/Quit policy is implemented; live acceptance remains.** The second pass defers termination until the operation finishes, quits on success, and cancels quitting/reopens the main window on failure. Regression tests cover the policy and completion notifications. Test the actual AppKit/SwiftUI window behavior on a slow external disk before considering this fully verified.
3. **Recording sessions are a visible product gap.** A multi-session DRP currently tells an app user to use CLI `--session`; there is no native session chooser. Add a session selection flow only with fixtures that verify the associated media paths. The current refusal is safer than choosing silently.
4. **Updates are manual, not automatic.** The menu opens GitHub; installing a new download requires quitting and replacing the same app. Both `/Applications` and `~/Applications` can contain a copy, and the Quick Action prefers the former. A future updater needs signature verification, rollback, and a defined installation location. A renamed/moved app is not found by the fixed-path Quick Action lookup.
5. **Parity means engine output for matching options.** The Python CLI still includes unpaired WAVs by default; the GUI and interactive fallback deliberately start with no extras. The fallback dialogs do not expose the app's transition/program controls. Test these entry points separately; do not market identical UI or defaults.
6. **Fresh transparent screenshots are still required for the next release.** The gallery depicts released 1.1.0, not the revised workspace. Keep native PNG alpha edges and no CSS masking/borders/rectangle shadows. The previous pass fixed gallery presentation and narrow-width stacking; this audit checks static site contracts, not a new browser/device matrix.
7. **Native acceptance is incomplete.** Test long custom names, eight camera inputs, many WAVs/warnings, light/dark appearance, keyboard-only navigation, VoiceOver, Reduce Transparency, small displays, minimum macOS 15, and real Intel hardware. The fixed-size conversion-details sheet and completion button group deserve attention at the narrowest window size.
8. **Release acceptance is incomplete.** Build/signing self-checks do not establish a clean-download Gatekeeper launch, successful replacement of a running installation, exFAT failure recovery, or a new Final Cut import. Exercise the actual downloaded release before describing those as verified. No release was dispatched during this audit.
9. **Supply-chain controls can be tighter.** Actions use major-version tags rather than immutable commit pins. Consider pinning reviewed revisions with automated update PRs and a protected release environment. Do not rotate credentials or change repository permissions as part of a routine UI audit.

## Website and documentation judgment

Keep the website short: the problem, a free download, GitHub, the recording workflow, and honest compatibility limits. GitHub and the MIT license are already prominent. Avoid adding more feature cards or marketing sections. Existing tests check canonical/social metadata, structured-data references, readable FAQ parity, local links, image metadata, and preservation of screenshot edges. They do not prove search ranking, bot discovery, or accessibility acceptance.

Use current docs as the entry point, with historical validation below them. Preserve the distinction between vendor guidance, observed ATEM logs, synthetic tests, and Final Cut round trips. Do not silently rewrite old evidence to make the current build appear more widely verified.
